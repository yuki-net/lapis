# 設定のスコープと所有者

設定を追加する開発者と、設定 UI を変更する開発者が、値の所有者・保存先・表示をどこで決めるかを判断するための正本。型や列挙値の一覧は `contracts/domain/settings` のコードを正とする。

## 不変条件

- 所有者は `User` / `Host` / `ProjectShared` / `ProjectLocal` の4スコープだけとし、適用順はこの並び（後ろほど強い）。
- 項目ごとに保存を許すスコープは定義データが宣言し、保存側は宣言外のスコープを拒否する。Host や Project で意味が変わる項目だけ、そのスコープを許可する。
- 定義データがキー・表示ラベル・入力方法・候補・既定値・許可スコープの唯一の正本である。UI は定義から画面を組み立て、キーやラベルを画面側へ複製しない。
- 保存は所有者ごとの `SettingsRepository` が行う。1つのスコープに複数の保存元を作らない。
- UI は解決済みの `ResolvedSettings` だけを読み、スコープや優先順位を画面側で再計算しない。
- Terminal の既定プロファイルは設定 `terminal.default-profile` が持つ。候補は Host が `terminal.list_profiles` で公開した一覧から供給し、Client は固定候補を持たない。未設定、または Host が公開しない ID は Host の既定へ倒す。

## 解決と保存

- 解決順は `User` → `Host` → `ProjectShared` → `ProjectLocal`。`SettingsContext` が持たないスコープは参照しない。定義の既定値はどの文書にも値が無いときだけ使う。
- 解決結果は「値」と「どのスコープが保存しているか」を保持し、後者は出所表示にだけ使う。
- 書き込みは所有者の repository へそのスコープの文書全体を渡し、成功した場合だけ共有 state と購読者を更新する。失敗した変更は表示にも残さない。
- 保存中も読み取りを待たせない。書き込みは state の書き込みロックで直列化し、`SettingsSession` と `SettingsCoordinator` の worker が UI thread の外で保存する。
- 同じ画面操作で変わる複数項目は1つの文書としてまとめて保存し、一部だけ反映しない。
- 保存形式は version 付き。旧 `settings-v1.json` は読み込み時だけ読み替え、新形式を優先する。未知の version は既定値へ黙って戻さずエラーにする。

## 範囲外

- Host スコープの設定ファイル読み書きと、Host 設定の RPC 編集 UI。
- ProjectShared / ProjectLocal のリポジトリ内ファイル読み書き。
- 現状は `User` スコープだけが `LocalUserSettingsRepository` で永続化される。他スコープは型・解決・保存契約の対応までを用意し、保存先を登録しない限り書き込みは拒否される。

## 設定 UI

- 左ナビは 分類 → 中間層 → ページ の3層。分類と中間層は分類専用の行で、クリックできず設定項目を持たない。設定項目を持つのはページだけ。
- 1ページ = 1つの葉。ページに並ぶ項目は定義データの `page` から決まり、画面側で項目を足したり別ページの項目を混ぜたりしない。
- ページ本文の供給元は `SettingPageContent` で宣言する。`Settings` は定義データの設定項目から組み立て、`Feature` は保存値を持たない実行時の状態（現在の接続情報など）を機能側が表示する。`Feature` ページは項目を持たないため、定義の検証でも項目を要求しない。
- 値は選択時に即時保存し、共有 state の更新購読で画面・テーマ・言語を反映する。保存を待つ間は選択だけを先行表示する。
- 定義に無いキーの保存は拒否する。UI 側の分岐で新しい設定を追加しない。
- Terminal の既定プロファイルの候補は Terminal Feature が Host から取得して公開した一覧を読む。Settings は Terminal Feature の entity に依存せず、公開された一覧だけを使う。
- 接続ページ（`connection.web`）は `Feature` ページで、ローカル Web のページ URL・Host URL・Workspace ID と、コピー／ブラウザーで開く操作を出す。アドレスは保存値にせず表示のたびに供給元から集めるため、Tailscale の IP 変更などの後も現在の接続情報へ追随する。供給元を持たない起動構成（Web 側など）では、このページをナビへ出さない。

## 追加手順

1. 定義データへキー・ラベル翻訳キー・入力方法・許可スコープ・既定値を追加する。
2. 表示文言を両ロケールへ追加する。
3. 新しい所有者が必要な場合だけ、そのスコープの `SettingsRepository` を実装して `SettingsSession::attach` へ渡す。
