# Architecture

この文書はLapis全体に関わる**設計の理由と守るべき意味**を扱います。現在のcrate配置やディレクトリ一覧はソースコードが正本です。プロトタイプの再構築を禁止しません。

## Clientと実行環境

LapisはRustを中心に、ネイティブのClientと、ファイル・Git・プロセス・Agentなどを扱う実行環境の分離を目指します。現時点ではGPUI Desktopを主要な検証対象とします。

Clientはfocus、selection、scroll、画面構成、描画cacheを所有し、実行環境はファイル・プロセス・実行状態などの正規状態を所有します。UIが直接OS資源を操作したり、複数の表示側が独立に正規状態を上書きしたりしないためです。

LocalとRemoteは異なる接続方法であっても、操作の意味と所有権をできる限り共有します。通信方式、crate境界、具体的なAPIは必要に応じて変更できます。

## 責務と状態

- 会話の履歴、Agentの実行、Worktree、プロセスのライフサイクルは同じ概念ではありません。画面やタブの寿命を実行資源の寿命に直結しません。
- 状態の所有者と更新の入口を明確にします。複数の独立した正本を作りません。
- 非同期の応答には必要に応じて世代・revision等を使い、古い結果を新しい状態へ誤適用しません。
- 外部CLI・SDK・OS固有形式を、必要もなく複数領域へ広げません。
- 共通の抽象化は実際の利用者・変更理由がある場合に導入し、将来像だけの空の境界は作りません。

## この文書に書かないこと

詳細な型、コマンド、フォルダ構成、ライブラリのバージョン、個別機能の内部仕様はここで管理しません。利用者向けの操作は `docs/site/`、個別の技術的制約は `docs/specs/`、実装・テストの現在地はコードとCIを確認してください。
