# Lapis documentation

リポジトリに残す文書は、**書かないと失われる判断・仕様・検証方法**に限ります。ページを増やすこと自体は成果ではありません。

## 情報の置き場所

| 場所 | 所有する情報 |
| --- | --- |
| `README.md`（ルート） | プロジェクトの入口 |
| `AGENTS.md`（ルート） | Agentへの最小限の共通作業指示 |
| `docs/*.md` | 複数領域に跨る、長く有効な基礎文書 |
| `docs/site/` | 利用者が観測できる操作・設定・仕様。将来の公開サイト |
| `docs/specs/` | 内部実装の契約・技術的制約・設計理由 |
| 各領域の `README.md` | その領域だけの責務・背景・参照先 |
| Issue・PR | 進行中の仕事、議論、時限的な設計判断 |
| 必要になったときだけの検証資料 | 複雑な不具合の再現スクリプト・測定結果など |

`docs/specs/` の「内部」は**サイトに掲載しない**という分類で、機密保管場所ではありません。このリポジトリは公開されているため、秘密情報や認証情報を置かないでください。

## 文書に残すかの判断

1. 誰が、いつ、この情報を参照しないと何を判断できなくなるか説明できるか。
2. ソース、テスト、CI、既存文書、PRの履歴だけで十分ではないか。
3. すでに正本があるなら新規ページを増やさず、そこを更新できないか。
4. 具体的なコード構造が変わっても残る情報か。変わるならコード・テスト側を正とする。
5. 未確定事項を決定済み・実装済みと誤認させないか。

**同じ仕様を公開Docsと内部仕様へ複製しません。** 利用者に見える振る舞いはサイトが、なぜその振る舞いを維持するかという内部制約は仕様書が所有します。

## 局所的なREADME

一律にすべてのディレクトリへREADMEを置かない。領域独自の説明が複数のファイル・作業に関わる場合だけ作成します。親には子の詳細を集約せず、役割と参照先を記載します。

READMEはCodexへの自動適用指示ではありません。Agentは作業に関係するREADMEだけ読み、共通の必須ルールはルートのAGENTS.mdに残します。

古い資料は修正・統合・削除し、現在の構造や過去のPhaseを固定する規則へ転用しません。
