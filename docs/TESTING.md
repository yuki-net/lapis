# Testing

この文書は検証の考え方を示します。**実際のCIジョブとコマンドの正本は `.github/workflows/`** です。対象プラットフォームや導入済み機能は、古いPhase文書ではなく現状の実装・CIで判断します。

## 検証

- 変更した領域と直接依存する領域を対象に、対応するformatter、build/check、lint、testを確認します。
- バグ修正では可能なら最小の回帰テストを追加します。
- 共通契約を変更したら、利用側も確認します。確認できない対象は未検証として報告します。
- テスト失敗を隠すためにassertionを削ったり、検証を無効化したりしません。

## ネイティブGUI

Desktopのコンパイル成功は画面と操作の検証ではありません。WindowsのGPUI UI変更は、利用できる環境でネイティブアプリを起動し、変更した操作と描画を確認します。

Agentが実画面を操作できない場合は、検証済みと報告せず、起動・操作手順と未確認箇所を明示します。GUIアプリの動作中はユーザーの作業セッションを勝手に奪わないでください。

## CIの範囲

現在の `.github/workflows/ci.yml` はBackend・Windows Desktop・Mobile・Webをチェックします。これは**現行のジョブ一覧**であって、将来の製品優先順位ではありません。CLIなど、まだ独立したジョブがない対象を「検証済み」と扱わないでください。
