# Internal specifications

この領域は、利用者向けサイトに公開することを目的としない**実装上の契約と設計理由**を扱います。

- 機能の内部契約と、領域を跨ぐ具体的な責務・依存制約を置きます。全体の判断原則は `../ARCHITECTURE.md`、利用者に見える仕様は `../site/` に置きます。
- コードやテストで十分な型、列挙値、ファイル一覧は重複させません。
- 採用済みの不変条件と、未検証の設計案を区別します。
- 内容が増えた領域だけディレクトリを設け、その場合に限って `README.md` を追加します。
- 複雑なバグ調査は、必要なときだけ再現資料と結果を保存し、仕様を水増ししません。

このリポジトリは公開されています。内部仕様であっても機密情報は書かないでください。

- [責務と依存方向](architecture.md): 機能追加時の状態所有・配置判断と依存検査。
- [設定のスコープと所有者](settings.md): 設定値の所有者・保存先・解決順と、設定 UI が定義データから画面を作る規則。
- [認証とセッション](auth.md): Host/Client の認証方式、OIDC 検証、Session の所有と失効。
- [配布と更新の土台](distribution.md): package と署名付き manifest の生成・配置、install layout、データ世代と credentials の置き場。
