# Design principles

LapisのClientに共通する視覚的な意図を記録します。UIの確定仕様や未実装画面の詳細を固定する文書ではありません。具体的な色、サイズ、Token、コンポーネントの有効な値は実装を正とします。

## 方針

- EditorやTerminalの情報を優先し、装飾を増やしすぎない。
- Panelなどの領域は、表面の明度差・余白・控えめな境界で区別する（Flat Islandの考え方）。
- 色・余白・Typographyは再利用可能な意味的Tokenを優先し、画面ごとの独自値を増やさない。
- 同じ役割の操作では、見た目、focus、hover、keyboard操作、状態の意味を合わせる。
- 未実装機能を操作可能に見せない。Loading、Disabled、Disconnected、Errorは必要に応じて区別し、回復方法を説明する。
- Native DesktopとMobileでは操作環境が異なる。外観やレイアウトを無理に共通化しない。

## 変更の判断

新しいUIパターンが必要なら既存の実装と比較し、利用者にとっての違いと理由を説明します。過去に書かれた数値や画面配置を維持すること自体を目的にしません。

利用者向けに保証するUI動作はサイトの機能Docsに、個々のClientの実装上の注意は関係する領域のREADMEまたは具体的な内部仕様に置きます。
